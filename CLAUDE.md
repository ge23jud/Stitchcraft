# Proc App — Claude Context

## What this project is
"PL Spectrum Stitcher / Converter" — a Windows PyQt5 desktop app for processing photoluminescence (PL) spectroscopy data during Benjamin Haubmann's PhD at TUM. It stitches multi-file power-series spectra into a single spectrum, converts between file formats (.origin / HDF5), visualizes spectra, and runs peak-fitting / threshold-detection analysis.

## Key facts
- **Entry point**: `stitchcraft.py` — builds the `QApplication`, applies the `qt_material` `dark_teal.xml` stylesheet, calls `plotting.apply_pg_theme()`, then shows `StitchApp`.
- **Main window**: `app.py` — `StitchApp(QMainWindow)`, a `QTabWidget` hosting the tabs below.
- **Platform**: Windows-only PyQt5 app (no PySide/Qt6 constraint otherwise).
- **GitHub**: https://github.com/ge23jud/Proc.git
- **Dependencies**: pinned in `requirements.txt` (PyQt5, pyqtgraph, numpy, h5py, scipy, pandas, qt-material, opencv-python, Pillow, matplotlib — matplotlib is only needed because `nw_analysis.py` and `pl.py` import it at module level; see the `plotting/` note below). No `pyproject.toml`/`setup.py`.

## Tabs (`tabs/`)
- **`stitch.py`** — "Stitch / Convert": one tab, two independent converters selected by a "File type" dropdown at the top of the sidebar — adding a third converter later is just another combo entry plus another sidebar page, nothing else needs restructuring.
  - **"PS (.origin) → HDF5"** (the original, pre-2026-08 standalone Stitch/Convert flow): load `.origin` power-series files, preview spectra, pick per-pair overlap "transition spans" (draggable region), dark-spectrum subtraction, power calibration, save as HDF5 or `.origin`.
  - **"TRPL (.dat) → HDF5"** (originally the standalone "Convert" tab; merged into this one 2026-08): batch-converts PicoHarp 300 TRPL histogram `.dat` exports to HDF5 (see `io_utils._parse_trpl_dat`). Load one or more `.dat` files, select each in the list and enter the power it was measured at (mW) — power is necessarily per-file since each TRPL scan is one power point, unlike the PS mode's single multi-power-step `.origin` files. Rep. rate (MHz) and spot diameter (µm) are global to the batch and, like the two power-calibration files (atBS/atSample, same format/autosearch idea as PS mode), are **required**, not optional — Pump_fluence and calibrated Power can't be computed without them. "Autosearch" walks each input file's directory *and its parent* (TRPL `.dat` files commonly sit one level below where a sibling `Calibration/` folder lives, e.g. `.../<dataset>/Calibration/` next to `.../<dataset>/TRPL/*.dat`, rather than inside the same folder as PS mode's flat layout) and recurses into any `Calibration/` folder found to handle per-laser subfolders (`Calibration/TiSa`, `Calibration/HeNe`); if that recursion turns up more than one atBS or atSample candidate it's treated as genuinely ambiguous (wrong laser calibration silently applied would be a real correctness bug) and surfaces all candidates in a dialog instead of guessing — the user picks via the per-role "Load…" buttons. "Convert to HDF5" writes one `.h5` per file with a power assigned, next to its source `.dat`, skipping/report­ing files with no power set. Output datasets: `Counts` (raw histogram), `Times` (`0, ns/channel, 2×ns/channel, …`, from the `#ns/channel` header line) with root attr `TimesUnit="ns"`, `Power_uncalibrated`/`Power`/`Pump_fluence` (1-element arrays, mirroring PS mode's dataset+units-attr convention so they stay `_read_h5_spectrum`-compatible), and root attrs `Date` (raw date/time string from the `.dat`'s first header line), `rep_rate_mhz`, `spot_diameter_um`. The atBS/atSample→transmission-factor OLS fit (`P_sample = a · P_BS`) is shared between the two modes via `io_utils._compute_power_transmission()` so both compute it identically.

  Implementation note: the two modes share nothing but the "File type" combo and the canvas/toolbar on the right (a `QStackedWidget` swaps the sidebar page; only one mode is ever visible, so there's no state conflict) — every widget and state variable is namespaced `_ps_*` or `_trpl_*`, i.e. they're really still two independent former-classes' worth of code living in one file. Switching the combo mid-work doesn't discard the other mode's state: leaving PS mode while mid-span-selection tears down the interactive `DraggableSpan` and hides the pair-nav bar but keeps `_ps_mode`/`_ps_pair_idx`/etc., so switching back to "PS" re-arms the selector on the same pair via `_ps_draw_pair()`; leaving/entering TRPL mode just redraws whatever `.dat` file is currently selected in its list (or a welcome message if none).
- **`trpl.py`** — "TRPL" (added 2026-08, unrelated to the "TRPL (.dat) → HDF5" *converter* above other than sharing a file format): load a single TRPL histogram HDF5 file (as written by `stitch.py`'s TRPL-conversion mode, via `io_utils._read_trpl_h5_file`) and fit N user-picked time windows to a single-exponential decay to extract lifetimes. Plots `Counts` vs. `Times` on a log-y axis using the same downsampled/`antialias=False` technique as the TRPL-conversion preview (large histograms, smooth pan/zoom). The user types the number of fits N, then clicks through N fit-range selections one at a time: drag a `DraggableSpan` over the desired time window (seeded at an equal 1/N slice of the axis as a starting point), a linear fit `ln(Counts) = a·Times + b` is recomputed live on every drag-release (points with non-positive `Counts` are masked out before taking the log; fewer than 3 remaining points skips the covariance estimate rather than hitting `numpy`'s rank-deficient warning, mirroring `analysis.py`'s threshold fit) and its equivalent `exp(b)·exp(a·Times)` curve is overlaid on the data immediately for a live preview, then "Confirm & next range" locks it in and advances (confirmed ranges/curves are redrawn as a shaded region + solid line on every rebuild). "Save fit results to HDF5" writes an `analysis` HDF5 subgroup (recreated fresh, same convention as `analysis.py`'s save) with `FitParameters` (n×2: `[a, b]`), `FitCovarianceMatrix` (n×2×2), `FitRanges` (n×2 `[xmin, xmax]` in ns — same `(n, 2)` shape convention as `analysis.py`'s `FitWindows`), `Lifetime` (n: `-1/a`), and a `FitFunction` group attribute — a descriptive string, not a live Python callable, since HDF5 has no native way to store one.
- **`visualizer.py`** — "Visualizer": like `stitch.py`, one tab with a "File type" dropdown (`QStackedWidget` sidebar page + one shared canvas) — "Powerseries" and "TRPL" (added 2026-08; unrelated to `stitch.py`'s TRPL-conversion mode or the standalone `trpl.py` tab other than sharing HDF5 schemas). State/widgets namespaced `_ps_*`/`_trpl_*`, same convention as `stitch.py`.
  - **"Powerseries"**: load one or more HDF5 files into a shared list; two dropdowns — **Y data** (`SpectraDiff`, `Spectra_raw`, `PeakArea`, `PeakIntegral`, `Specsum`) and **X data** (`Wavelength`, `Energy`, `Power`, `Uncalibrated Power`, `Pump Fluence`) — pick what gets plotted. Each loaded file is checked for which of these actually exist (`_vis_ps_load_file()`'s `y_avail`/`x_avail` sets; nothing is synthesized — a missing dataset just isn't offered), and the two dropdowns mutually filter each other since every option belongs to exactly one of two mutually-exclusive modes: "spectra" (SpectraDiff/Spectra_raw × Wavelength/Energy) or "scalar" (PeakArea/PeakIntegral/Specsum × Power/Uncalibrated Power/Pump Fluence). Only the *passive* combo (the one not just changed) gets narrowed to the active one's compatible-and-available options — narrowing *both* on every change was tried first and created a dead end (once "scalar" narrowed the Y list, "SpectraDiff" was no longer offered anywhere to switch back with); the active combo always keeps its full list, so the round trip back to the other mode is always reachable through it. Spectra-mode legend labels show pump fluence if the file has it, else calibrated power, else uncalibrated power. "Inspect peaks…" replicates the Analysis tab's live "Inspect fits" view (see below) purely from a saved file — requires the `analysis` subgroup and specifically `FitWindowX`/`FitWindowRawY`/`BackgroundData`/`FitParameters` (a critical-path error if the subgroup or those datasets are missing, e.g. a file saved before the 2026-08 schema extension). "Show Data" (unchanged) opens a dialog listing every dataset/group/attribute in the selected file's HDF5 structure (via `io_utils._h5_contents_summary()`). The old "Legend quantity" radio group (power / power density / pump fluence) and "Plot integrated spectrum vs pump fluence" checkbox were removed 2026-08 — both are strictly subsumed by the new X/Y dropdowns plus the automatic legend rule.
  - **"TRPL"**: load one or more TRPL HDF5 files (via `io_utils._read_trpl_h5_file`) into their own list, overlaid on a log-y, downsampled canvas (same `setClipToView`/`setDownsampling`/`antialias=False` technique as `trpl.py`/`stitch.py`'s TRPL-conversion preview — smooth even at ~65k points/curve). A "Show fit intervals & functions" checkbox toggles, per file, an `analysis`-subgroup overlay (shaded `FitRanges` + `exp(b)·exp(a·Times)` curves from `FitParameters`, colored to match that file's curve) if present; a lifetime-values label lists each loaded file's `Lifetime` array as text (or "—" if the file has no saved fit).
- **`analysis.py`** — "Analysis": peak-picking → fit-window selection → `fit_nw`/`integrate_spectra` (via `nw_analysis.py`) → threshold detection (drag-select ASE region, linear fit, threshold ± error) → L-L curve plot → save results into the HDF5's `analysis` group. A click-driven wizard/state machine (`self._ana_mode`). "Inspect fits" (added 2026-08, mode `"inspect"`): once `fit_nw` has run, pick a peak from the dropdown and click "Inspect…" to cycle per-power-step (◀/▶) through that peak's individual fits — each view overlays the full raw spectrum, the windowed raw data highlighted, the exact fit interval shaded (`DraggableSpan(..., movable=False)`, a static replay, not draggable), and the fitted Gaussian/Lorentzian curve (evaluated from `nw.fits[j][i].popt` via `nw_analysis._gauss_n_model`/`_lorentz_n_model`, with the interpolated local background from `nw.fit_data[j][i]` added back so it overlays the raw-counts curve rather than the background-subtracted one) — a QA tool for eyeballing convergence/tracking-drift per step rather than trusting the aggregate L-L curve. "✓ Close inspect" returns to the L-L curve. The save routine persists enough of this (`FitWindowX`/`FitWindowRawY`/`BackgroundData`/`FitParameters`, extended 2026-08 — previously only the background curve's *values* were saved, not its x-positions or the raw windowed y, which wasn't enough to reconstruct the overlay from the file alone) that the Visualizer tab's "Inspect peaks…" can replicate this exact view without a live fitting session.
  - **Fixed 2026-08**: `_ana_save()` read `nw.fit_function` for the saved `FitFunction` attribute, but `nw_analysis.fit_nw()` actually sets `nw.fit_model` — the attribute name never matched, so every saved file's `FitFunction` was silently always the getattr default `"gaussian"` regardless of which fit function the user actually picked (gauss2, lorentz1, ...). Likewise `nw.background_type` was read but never set anywhere, so `FitBackground` was always its `"linear"` default too. Both are now real: `fit_nw()` sets `nw.background_type = subtract_fit_background` alongside its existing `nw.fit_model = fitfunction`, and `_ana_save()` reads the correct `fit_model` name. Caught while building the Visualizer's Inspect-peaks feature, which parses `FitFunction` (e.g. `"gauss2"` → 2 sub-Gaussians) to pick the right model function — with the bug, every file claimed `"gaussian"`, a string the `re.match(r"(gauss|lorentz)(\d+)", ...)` parse doesn't even match.
- **`spotsize.py`** — "Spotsize": load an Excel/text beam-scan file, select two spans on the derivative curve, Gaussian-fit the edge, compute the 95.4% width and beam diameter (Δx × sin(angle)).
- **`sem.py`** — "SEM": nanowire width/height/angle measurement from SEM TIFF images, a Python port of the "smarter SEM" MATLAB toolset (`\\nas.ads.mwn.de\tuze\wsi\e24\SQN\Researchers\Haubmann Benjamin\01_PhD\10_Scripts\smarter SEM`). Three modes: **Automated** (whole-image binarize → contour-trace → `cv2.minAreaRect` fit, with edge/size/tilt rejection rules and a per-image "skip IDs" list, port of `edgeDetect.m`), **Semi-automated** (click near a wire → auto-crop a physical-size window around it → detect the tallest accepted blob in the crop, falling back to a manual 2-click measurement if detection fails or the result is too short, port of `edgeDetect_semiauto.m`), and **Manual** (plain 2-click distance measurement tagged with a measurement-type label, port of `click_on_image.m`/`smarterSEM.m`). All three modes share one results table (exportable to CSV) and a live mean±std stats readout (replacing the separate `getValues.m`/`combined.m` post-processing scripts). Core image-processing logic lives in `sem_utils.py` (root, no PyQt imports); pixel scale is parsed by regex-scanning the TIFF's embedded ASCII metadata footer for `Pixel Size = <value> <unit>` (editable per-image if not found or wrong). Adds `opencv-python` and `Pillow` as dependencies.
- **`plot.py`** — "Plot": load one or more HDF5 spectrum files, preview each as PL Intensity (arb. units) vs. energy (one line per power step, colored dark→light by ascending pump fluence via matplotlib's `plasma` colormap, legend outside the axes titled "Pump Fluence (uJ/cm²)" with unit-less values converted from the file's mJ/cm² to µJ/cm² — falls back to power in mW, with its own "mW" suffix per entry and a "Power (no fluence in file)" title, if a file has no `Pump_fluence` dataset; `plot_utils._legend_ncols()` picks a legend column count from the figure height and entry count so a long single-column legend can't shrink `constrained_layout`'s axes to squeeze the plot), then "Save all as PNG" writes one `.png` per loaded file next to its source `.h5` (same basename). **Deliberate exception to the pyqtgraph-only rule below**: this tab embeds a real `matplotlib.figure.Figure` via `FigureCanvasQTAgg` instead of `PGCanvas`, because the saved image must be a literal matplotlib figure (WYSIWYG with the preview) — figure construction lives in `plot_utils.py` (root, no Qt/pyplot imports, uses the `Figure` OO API directly so `savefig` works for any format regardless of the attached interactive canvas).
- **`fit.py`** — "Fit": load one Powerseries HDF5 file (via `io_utils._read_h5_spectrum`) and plot its highest-power `SpectraDiff` vs. `Energy`; pick a fit function from a dropdown (`FIT_FUNCTIONS` registry — currently only "Gaussian", reusing `pl._gaussian`), drag a single `DraggableSpan` to select the fit region, click "Fit" to run `scipy.optimize.curve_fit` over that span. The fit curve is overlaid on the spectrum and a `QDialog` pops up showing each parameter's value ± standard error (from `sqrt(diag(pcov))`) plus R². Adding a new fit function later just means adding an entry to `FIT_FUNCTIONS` with a callable and its parameter labels.

## Shared modules
- **`io_utils.py`** — pure data I/O: `.origin`/HDF5 read-write, power-calibration parsing, HDF5 spectrum reading (`_read_h5_spectrum`, used by the Plot tab), HDF5 structure introspection (`_h5_contents_summary`, used by the Visualizer tab's "Show Data" dialog), TRPL `.dat` parsing/writing (`_parse_trpl_dat`, `_write_trpl_h5_file`, used by the Convert tab) and TRPL HDF5 reading (`_read_trpl_h5_file`, used by the TRPL tab), and the shared atBS/atSample transmission-factor fit (`_compute_power_transmission`, used by both `_write_h5_file` and `_write_trpl_h5_file`). No UI, no plotting.
- **`sem_utils.py`** — pure image-processing logic for the SEM tab: TIFF+scale reading, blob detection/rectangle-fit, crop, and 2-point measurement. No UI.
- **`plot_utils.py`** — pure matplotlib figure-construction logic for the Plot tab (`build_spectrum_figure`, `png_path_for`). No Qt imports; `io_utils._read_h5_spectrum()` supplies the data it plots.
- **`nw_analysis.py`** — Python port of the MATLAB nanowire PL analysis pipeline (`main_Benni.m`/`Analysis.m`/`Nanowire.m`). Used by `analysis.py` as `import nw_analysis as nwa` for `fit_nw`/`integrate_spectra` on a `SimpleNamespace` "nanowire" object (`_new_nanowire()`). Moved into this repo from a sibling `..\Plot\` folder (2026-07) — previously reached via `sys.path.insert`, now just a root-level module like `io_utils.py`/`sem_utils.py`. Still imports `matplotlib.pyplot`/`matplotlib.widgets` at module level for its own standalone interactive functions (`set_startconditions`, `thresholds`), but `analysis.py` always calls `fit_nw`/`integrate_spectra` with `show_progress=False`, so those matplotlib windows are never triggered from this app — matplotlib is a hard import-time dependency of this module even though it's otherwise out of scope for the app's own plotting (see below).
- **`pl.py`** — numeric helpers: origin-file parsing, spectrum stitching (`_stitch_counts`), Gaussian fitting, `_HC_EV_NM` (eV↔nm constant), used by `io_utils.py`, `stitch.py`, `visualizer.py`, `analysis.py`, `spotsize.py`. Copied into this repo (2026-07) from `C:\Users\ge23jud\PL Helper\pl.py`, which is its own separately tracked git repo (`github.com/ge23jud/PL-Helper.git`) — deliberately a **copy**, not a move, so that other repo's history/remote stays intact and other tools depending on it are unaffected; this repo's copy is now the one all local imports resolve to. ## Plotting architecture — `plotting/` package
Every tab except `plot.py` plots exclusively through PyQtGraph via the shared `plotting/` package (migrated off Matplotlib in 2026-07). Each such tab imports only from `plotting` (never a submodule directly). `plot.py` is the one deliberate exception — see its entry above — and embeds matplotlib directly via `FigureCanvasQTAgg`, not `PGCanvas`. Note `matplotlib` came back as a `requirements.txt` dependency in 2026-07 when `nw_analysis.py` was moved into this repo — originally needed only for that module's own (unused-from-this-app) interactive functions and `pl.py`'s, `plot.py`'s embedded preview is the first tab to actually render matplotlib on-screen.

- **`canvas.py`** — `PGCanvas(pg.GraphicsLayoutWidget)`: the shared embeddable canvas. `reset_axes()` clears curves/ROIs/legend/colorbar and returns a fresh `plot_item` (full clear-and-rebuild on every redraw, matching every tab's existing redraw pattern — no incremental updates). `sigDataClicked(x, y, button)` replaces matplotlib's `button_press_event` for click-driven picking (used by `analysis.py`). `draw_idle()` is a no-op kept only so old call sites didn't need touching.
- **`theme.py`** — `apply_pg_theme()` (call once at startup, before any `PGCanvas`), `TAB10` palette, `PLASMA` colormap — matched to the app's dark `qt_material` theme.
- **`multiline.py`** — `MultiLinePlotter` + `LineColorScheme` strategy classes (`CategoricalScheme` = tab10-by-index, `SequentialScheme` = plasma-by-value, `LogAlphaRamp` = log-scaled opacity wrapper) — covers every "color N lines by file or by power" pattern across `stitch.py`/`visualizer.py`/`analysis.py`.
- **`colorbar.py`** — `GradientLegend(pg.ColorBarItem)`: a standalone plasma gradient legend (not attached to an image), used wherever lines are colored by power.
- **`regions.py`** — `DraggableSpan` (wraps `pg.LinearRegionItem`; one class serves both the interactive picker role and the "replay a stored span" role via `set_range()`) and `DraggableRect` (wraps `pg.RectROI`; a persistent resizable box — deliberately different UX from matplotlib's click-drag `RectangleSelector`, confirmed acceptable). Both track their own add/remove lifecycle since `reset_axes()` wipes them on every redraw.
- **`scatter.py`** — `RecolorableScatter`: thin wrapper over `pg.ScatterPlotItem` for per-point recoloring (analysis.py's threshold-region highlighting).
- **`annotations.py`** — `FilledRegion` (`pg.FillBetweenItem` wrapper) and `MeasurementArrow` (hand-built double-headed arrow + label composite — no built-in PyQtGraph equivalent; spotsize.py's only consumer).
- **`toolbar.py`** — `make_pg_toolbar(canvas)`: a minimal 2-button toolbar (Export Image…, Reset View) replacing matplotlib's `NavigationToolbar2QT`. Pan/zoom is handled by PyQtGraph's built-in mouse interactions (scroll-zoom, drag-pan, right-drag box-zoom) instead of dedicated buttons.

**Known pyqtgraph gotcha (worked around in `canvas.py`)**: toggling `setLogMode` right after `reset_axes()` can hit a `10**range` overflow if the ViewBox still holds a stale large linear range from whatever was plotted before the clear. `reset_axes()` explicitly resets the view to a small known range before re-enabling auto-range to avoid this.

**Known pyqtgraph gotcha — large curves are slow with the app-wide antialias default**: `theme.py`'s `apply_pg_theme()` sets `antialias=True` globally, which combined with a non-default pen width forces pyqtgraph's slow per-segment rendering path; without downsampling, every pan/zoom also repaints every point. Fine for the few-thousand-point curves most tabs plot, but heavily laggy for large ones (`stitch.py`'s TRPL-conversion mode's ~65536-point TRPL histograms, `trpl.py`'s, `xrd.py`'s large scans). Fix, applied at each such call site: `ax.setClipToView(True)`, `ax.setDownsampling(auto=True, mode="peak")`, and `MultiLinePlotter.plot(..., width=1.0, antialias=False)` — the `antialias` kwarg on `MultiLinePlotter.plot()` (added for this) defaults to `None`, inheriting the global setting, so every other call site is unaffected.

`PGCanvas.set_welcome(msg)` (added 2026-08 for `stitch.py`'s merged tab, also used by `visualizer.py`'s) updates and re-shows the welcome/placeholder screen — for a canvas shared across multiple modes (a "File type" switch) where each mode wants its own placeholder text instead of the one fixed at `__init__`.

**Known pyqtgraph limitation**: `pg.LegendItem` only renders items with an `.opts` attribute (`PlotDataItem`-like) — `LinearRegionItem`/`InfiniteLine` cannot be added via `legend.addItem(...)`. Span regions are identified by on-canvas color + sidebar labels instead of a legend entry; axvline-style markers use `InfiniteLine`'s own `label=`/`labelOpts=` instead.
